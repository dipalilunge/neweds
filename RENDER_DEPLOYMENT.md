# Engineering Design Studio - Render deployment

## Render settings

This project includes a `render.yaml` Blueprint configuration. It sets the admissions spreadsheet ID and the separate services-enquiries spreadsheet ID. The app uses the `EDS_GOOGLE_CREDENTIALS_JSON` secret at runtime.

### Required one-time Google setup

1. In Google Cloud Console, create a service account and enable **Google Sheets API** and **Google Drive API**.
2. Create/download a JSON key for that service account.
3. Open each spreadsheet and share it with the service account's `client_email` address from the JSON file. Grant **Editor** access.
4. Check the worksheet tab names. The configured defaults are `Admissions` for the admissions spreadsheet and `Service Inquiries` for the services spreadsheet. If the named tab is missing, the app uses the first existing tab (common for imported CSV files). Set `EDS_ADMISSIONS_WORKSHEET` / `EDS_SERVICES_WORKSHEET` in Render to the exact tab name you want. Existing non-empty headers are never overwritten; they must match the application fields.
5. In Render, open the web service -> **Environment** and set `EDS_GOOGLE_CREDENTIALS_JSON` to the complete contents of the service-account JSON file. Keep it secret; do not commit it to GitHub.
6. Set strong values for `EDS_ADMIN_PASSWORD` and `EDS_STUDENT_PASSWORD`. `EDS_SECRET_KEY` is generated by the Blueprint.
7. Deploy or trigger a manual deploy.

## Verify after deployment

1. Open the public site and submit a test admission using a test record.
2. Confirm the row appears in the admissions spreadsheet's configured worksheet.
3. Submit a service enquiry and confirm it appears in the services spreadsheet's configured worksheet.
4. Check Render logs if either submission fails. A local CSV fallback is not persistent on Render's ephemeral filesystem, so successful Google Sheets access is required for durable production records.

Do not paste service-account JSON into public chat, source code, or a public Git repository.
